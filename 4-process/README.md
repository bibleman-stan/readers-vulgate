# 4-process

How the work runs: improvement loops, pipeline and gates, operational protocols,
build pipeline, deployment infra, pending tasks, skills. Files are numbered
(`00-`, `01-`, …) because they read in order.

**Empty so far**, and one consequence is worth naming: this repo has **no
retraction log**, which `loop_health.py` reports at every session start. That is
a real gap, not an oversight of the reorg — nothing has been retracted here yet
because nothing has been adjudicated here yet.

The boundary against `3-project`: this tier is **how** the work runs, including
how deployment runs. `3-project` is **what** this corpus is and where it stands.

Part of the five-tier reader shape: `1-method` (canon) · `2-evidence`
(measurements and retractions) · `3-project` (the handbook) · `4-process` (how
the work runs) · `5-machinery` (code). The served site — `books/`, `data/`,
`index.html`, `sw.js`, `CNAME` — stays unnumbered at the root, because GitHub
Pages serves from there and numbering it would break the live domain.
